# Security Policy

## Supported versions

Security fixes are provided for the latest published release.

## Reporting a vulnerability

Do not open a public issue for vulnerabilities that could put users at risk. Use the repository owner's private security advisory form and include:

- affected version;
- reproducible steps;
- expected and actual behavior;
- relevant logs with usernames, paths, tokens and other personal data removed.

Do not attach malware samples, credentials or private game/account data to a public issue.

## Scope

W1SLEY Edition changes Windows settings only after a user action. Reports about privilege boundaries, unsafe command construction, untrusted executable launching, update integrity and incomplete rollback are especially useful.
